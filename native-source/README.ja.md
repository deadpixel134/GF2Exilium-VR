## 1.1.6 — 自動更新の修正

設定GUIの起動時に公開GitHubリリースを確認します。通知の **更新** を承認するとダウンロード・検証・インストールします。1.1.6以降はGitHub CLIのインストールやログインが不要です。

旧クライアントの固定許可リストが新しいビルドを拒否する問題を修正しました。クライアントはリリース・ファイルのハッシュ、種類、現在の所有権を確認し、検証済みの新インストーラーが最終ビルド検証・バックアップ・インストールを担当します。Clean・Dirtyの種類と設定は維持します。

1.1.4以前では今回一度だけ、希望するClean・Dirty ZIP全体を新しいフォルダーに展開し、付属の新しいGF2VR.Installer.exeで更新してください。更新確認が動作する1.1.5環境ではGUI更新を利用できます。旧版に必要なGitHub CLIがない場合も今回一度ZIPから更新してください。1.1.6導入後はCLI・ログイン不要でGUIから更新できます。

VR DLLは1.1.5と同一です。ログの初期値OFF、明示的ON設定と初回整理の除外、パネル・接触設定を維持します。インストール前にゲームと設定画面を閉じてください。

## 1.1.5 — ログ記録設定

Clean・Dirty共通で設定GUIに **診断 → ログを自動記録** を追加しました。初期値は **OFF** で、旧設定に項目がない場合もOFFです。保存後にゲームを再起動すると適用されます。

初回の更新インストール時に、ログOFFのユーザーの以前のVR自動ログを一度だけ整理します。**ログONのユーザーは既存ログを保持し、この初回整理から除外されます。** 後でOFFに変えても過去のログを遅れて削除しません。設定・他のMOD・手動で収集した資料は保持します。

問題の調査時にログを有効にしてください。ONでは同じビルドのログに追記され、容量が増加することがあります。

1.1.5では必要なCleanまたはDirtyのZIP全体を新しいフォルダーに展開し、付属の新しいGF2VR.Installer.exeで更新してください。旧設定アプリは新しいnativeプロファイルを拒否する場合があります。既存設定は保持されます。

## 1.1.3 — Clean / Dirty

現在の 1.1.3 は variants 配下の共通コードと種類別の生成ヘッダーを使います。両方を再構築するコマンド:

```powershell
./variants/build-variants.ps1 -Zig 'C:/Tools/zig/zig.exe' -Output './build-1.1.3'
```

1.1.3 は Clean/Dirty の製品ソースと別パッケージを公開します。native-source/variants/common は共通ネイティブコード、Clean/Dirty overlay は接触の有無による生成ヘッダー、managed は自作の手表示・接触コードです。それ以外の native-source 直下には従来の 1.0.2 ソースと再構築手順を保持します。

Quest 3 と Galaxy XR で報告された左右映像のずれは、アンチエイリアスが原因であると確認されました。VR を使用する前に、ゲーム設定のアンチエイリアスをオフにしてください。

1.1.3 は PR #1 の 3DMigoto 既定 wrapper モードとの互換性変更を Clean・Dirty の両方に反映します。ゲームの wrapper を保持し、VR コピーと OpenXR には実際の D3D11 デバイス/context を使用します。DLL と一致する設定アプリ・インストーラーを同梱します。

[3DMigoto](../docs/ja/3DMIGOTO_COMPATIBILITY.md) · [Build metadata](../docs/ja/BUILD_VARIANT_METADATA.md)

これは、GF2VR 1.0.2 に含まれるネイティブランタイム `BOOTSTRAP-FLEX-001` のビルドに必要なソース一式です。SHA-256 は次のとおりです。

```text
6215CEAFFFA46A3B89336DA73203122DD0095977206FDB395A1259F967B54771
```

Windows x64 上で、PowerShell 7、Zig 0.16.0、Windows 10 SDK 10.0.26100.0 の x64 `kernel32.lib` を使用してビルドします。

```powershell
./build-native.ps1 -Zig 'C:/Tools/zig/zig.exe' -Kernel32Library 'C:/Program Files (x86)/Windows Kits/10/Lib/10.0.26100.0/um/x64/kernel32.lib' -Output './build'
```

ビルダーは出力ディレクトリを Zig のキャッシュに使用し、終了後に呼び出し元のキャッシュ設定を復元します。11 個のランタイム補助ユニットと 4 個の MinHook ユニットをコンパイルし、ランタイムをリンクします。生成した DLL のハッシュがリリースと異なる場合は拒否します。`build-result.json` に、オブジェクトのハッシュ、コンパイラーのハッシュ、最終的な引数、DLL の比較結果を記録します。このビルドは DLL をインストール・読み込みせず、ゲームや XR ランタイムを起動しません。

`native-build.json` には、正確なビルドフラグとソースのハッシュを記録しています。`src/` には、現在の自作ネイティブコードと、このビルドが使用する生成済みパッケージヘッダーが含まれます。`managed/ActivityProducerEngineBridge.cs` は、埋め込まれたマネージドパッケージに対応する自作ブリッジのソースで、確認と開発のために提供しています。このネイティブ DLL の再ビルドは、リポジトリに含まれる生成済みパッケージを使用するため、ゲームのアセンブリを必要としません。マネージドパッケージの再生成は別の開発作業であり、合法的に入手した対応バージョンのゲームアセンブリが必要です。それらのアセンブリやアセットは、ここでは配布していません。

OpenXR と MinHook のソースの必要部分には、`third_party/` 内にそれぞれのライセンスを保持しています。ゲームの実行ファイル、Unity/GameAssembly のバイナリ、ゲームのメタデータ、ゲームのアセット、ユーザー設定、ログ、復元用ファイルは、このソース配布には含まれません。

1.0.2 のパス変更は、実行ファイルの隣にあるローダーと、対応する `vrmod` ディレクトリを探す部分です。標準の `GF2 Game/GF2_Exilium.exe` 構成では、従来どおり親フォルダーの `vrmod` を使います。それ以外の構成では、見つかった実行ファイルのフォルダーにある `vrmod` を使います。`version.dll` は常にその実行ファイルの隣にインストールされます。
