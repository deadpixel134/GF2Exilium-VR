## 1.3.3 — English

### Automatic VR reconnection

- Until now, if the VR session failed while the game was running, VR did not come back until the game was restarted. Now the failed session is cleaned up and a new session is created **up to 6 times, 10 seconds apart**. If a reconnected session stays up for 60 seconds or more, a later disconnection again gets up to 6 attempts.
- Reconnects after: frame submission, image or swapchain errors, a session lost by the VR runtime, and runtime event errors.
- Does not reconnect when: you exit the app from SteamVR or similar, you close the game, or the game's graphics device changes.
- This addresses the report "VR drops when first entering the Activity floor and does not come back, even after returning to the main menu". We confirmed that VR was never reconnected once a session failed, and fixed that. What triggers the disconnection (for example PC load) could not be confirmed because no log was available. If VR still does not recover, please send a log as described in [Saving and sending logs](https://github.com/deadpixel134/GF2Exilium-VR/blob/main/docs/en/LOGS.md).

### Saving and sending logs

- Added an **Open log folder** button to the Settings **Diagnostics** tab. The location is shown below the button; if no log exists yet, it explains how to turn logging on.
- New guide [Saving and sending logs](https://github.com/deadpixel134/GF2Exilium-VR/blob/main/docs/en/LOGS.md) on turning logging on and sending logs to the developer (four languages).
- Log file names in this version: Dirty `GF2VR-DIRTY-133-006.jsonl`, Clean `GF2VR-CLEAN-130-002.jsonl`.

### Other

- 1.3.2 was an internal candidate that was withdrawn and never published. Everything in 1.3.1 (including late head-pose re-acquisition) is included.
- The VR binary (native 006) is 1.3.1's 004 plus the reconnection above. Settings and Installer were rebuilt for the new VR binary; their version is 1.3.3.

### Verification scope and known limitations

- Reconnection was verified with host tests (36 retry-policy checks) and the 24 existing native test suites. A real disconnection could not be reproduced, so reconnecting on a VR device was not observed directly.
- This VR binary (Clean and Dirty 006) was verified by exact byte reproduction and host tests only; it has not been run in the game on a VR device. The reconnection code only runs after a session has ended with an error, and normal behavior is intended to be the same as 1.3.1.
- The lag/tilt feeling when turning the head on the Main screen is still under investigation.

### How to update

Close the game, then accept the update in Settings' new-version notice. For a manual install, extract the whole ZIP for your variant (Clean/Dirty) into a new folder and choose the game folder in the included Installer. Changed or missing installed files can be fixed with the Installer's Repair.

**Download:** pick one Clean or Dirty ZIP under Assets. The Source code ZIP is not an installation package.
