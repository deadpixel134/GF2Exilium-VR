## 1.3.3 — 日本語

### VR 接続の自動復旧

- これまでは、ゲーム実行中に VR セッションがエラーで切れると、ゲームを再起動するまで VR が戻りませんでした。今後は切れたセッションを片付けたあと、**10 秒間隔で最大 6 回** 新しいセッションを作って再接続します。再接続したセッションが 60 秒以上続いた場合は、その後の切断でも再び最大 6 回試します。
- 再接続する場合: フレーム送信・イメージ・スワップチェーンのエラー、VR ランタイムによるセッション喪失、ランタイムのイベントエラー。
- 再接続しない場合: SteamVR などでユーザーがアプリを終了した場合、ゲームを終了する場合、ゲームのグラフィックスデバイスが変わった場合。
- 「最初に活動層に入ると VR が外れ、メインメニューに戻っても復旧しない」という報告を反映しました。一度切れると再接続しない動作が原因と確認できたため修正しました。ただし切断のきっかけ(PC スペックによる負荷など)はログがなく確認できていません。それでも復旧しない場合は [ログの保存と送付](https://github.com/deadpixel134/GF2Exilium-VR/blob/main/docs/ja/LOGS.md) の手順でログを送ってください。

### ログの保存と送付

- Settings の **診断** タブに **ログフォルダーを開く** ボタンを追加しました。ボタンの下に保存場所が表示され、まだログがない場合は有効にする方法を案内します。
- ログを有効にして開発者に送る方法を [ログの保存と送付](https://github.com/deadpixel134/GF2Exilium-VR/blob/main/docs/ja/LOGS.md) にまとめました(4 言語)。
- このバージョンのログファイル名は Dirty `GF2VR-DIRTY-133-006.jsonl`、Clean `GF2VR-CLEAN-130-002.jsonl` です。

### その他

- 1.3.2 は内部候補として取り下げられ、公開されていません。1.3.1 の機能(目の描画直前の頭部姿勢再取得など)はそのまま含まれます。
- VR 実行ファイル(native 006)は 1.3.1 の 004 に上記の復旧機能だけを加えたものです。Settings と Installer は新しい VR 実行ファイルに合わせて再ビルドし、バージョンは 1.3.3 です。

### 検証範囲と既知の制限

- 復旧動作はホストテスト(再試行ポリシー 36 項目)と既存のネイティブテスト 24 種で確認しました。実際の切断を再現できなかったため、VR 機器で切断後に再接続される様子は直接確認していません。
- 今回の VR 実行ファイル(Clean・Dirty 006)はバイト単位の再現とホストテストのみで検証しており、ゲームと VR 機器で直接実行していません。復旧コードはセッションがエラーで終わったあとにだけ動作し、通常の動作は 1.3.1 と同じになるようにしています。
- Main 画面で頭を回したときの遅延・傾きの感覚は引き続き調査中です。

### 更新方法

ゲームを終了してから、Settings の新バージョン案内で更新に同意してください。手動インストールでは、使用する種類(Clean/Dirty)の ZIP を新しいフォルダーにすべて展開し、同梱の Installer でゲームフォルダーを選択してください。変更・欠落したインストールファイルは Installer の修復インストールを使えます。

**ダウンロード:** Assets から Clean または Dirty の ZIP を 1 つ選んでください。Source code ZIP はインストールパッケージではありません。
