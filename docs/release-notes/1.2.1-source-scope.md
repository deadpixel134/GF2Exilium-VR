The active native tree contains only the normalized union of exact Clean/Dirty NATIVE-BASELINE-003 product preprocessing dependencies, not the full development tree. ## Product build and desktop metadata

From native-source, with PowerShell 7, Zig 0.16.0 and Windows SDK 10.0.26100.0:

~~~powershell
./variants/build-variants.ps1 -Zig 'C:/Tools/zig/zig.exe' -Output './build-1.2.1'
~~~

The compiler SHA256 must match the release recipe. Product mainArgs/defines and helper compile flags are preserved from 003. The recipe's build/report hashes identify GF2VR-CLEAN-121-003 (FE4A7B3F...) and GF2VR-DIRTY-121-003 (F83E2711...). Generated overlays are exact 003 inputs. No B6 or observation opt-in is enabled. An exact two-flavor reproduction binds the reviewed release commonCore contract 6EDCB5FD... to those DLL hashes. The public closure source-manifest hash is separately reported and is not mislabeled as that release contract. Intentional source changes require -AllowSourceChanges and newly generated matching metadata.

From desktop-source, use the generated metadata explicitly:

~~~powershell
./vrmod/tools/build_desktop_private_runtime.ps1 -Application Configurator -BuildId RELEASE-CLEAN-121 -ProductVersion 1.2.1 -NativeMetadataRoot ../native-source/build-1.2.1/desktop-metadata -NativeFlavor Clean

~~~

The 50 nongenerated desktop files are exact canonical bytes. The two historical fallback files are replaced with the reviewed 003 generated VariantProfiles and Clean runtime contract. Actual GUI settings ownership includes performance.json; deployed wire files remain the legacy eight/nine-file set. Assembly informational revision retains the accepted 1.2.1 revision for byte reproduction. Private source-owner guards and machine paths are not published.

Game reference bytes and output DLLs are never committed.
