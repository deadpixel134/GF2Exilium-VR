# Build desktop tools for changed native sources

[한국어](../ko/BUILD_VARIANT_METADATA.md) | [English](../en/BUILD_VARIANT_METADATA.md) | [日本語](../ja/BUILD_VARIANT_METADATA.md) | [简体中文](../zh-CN/BUILD_VARIANT_METADATA.md)

Configurator and Installer strictly pin native DLL hashes. Keep those checks enabled and use the same metadata generated by a paired native build. Windows x64, PowerShell 7, Zig 0.16.0 and the Windows SDK are required. Run the commands below from the repository root.

The default build of released 1.1.3 source must reproduce the release hashes exactly. Add -AllowSourceChanges only for an intentional development change. Use a fresh output folder and build both variants together.

```powershell
./native-source/variants/build-variants.ps1 -Flavor Both `
    -Zig <zig.exe> -Kernel32Library <kernel32.lib> -Output ./native-source/variants/build
```

desktop-metadata contains VariantProfiles.generated.cs with actual DLL build IDs/hashes, a runtime-contract.json for each of Clean/Dirty, common-source-manifest.txt and metadata.json. Single-flavor builds do not generate it. Missing DLLs, mismatched report hashes and materialized common source drift are rejected.

Pass the same metadata to Installer and both Configurator builds, with a unique BuildId for each. Direct MSBuild users set GF2VRVariantMetadataRoot and Configurator GF2VRBuildFlavor. Omitting these properties uses the checked-in release contract; do not mix that output with changed DLLs.

```powershell
$metadata = (Resolve-Path ./native-source/variants/build/desktop-metadata).Path
$desktop = './desktop-source/vrmod/tools/build_desktop_private_runtime.ps1'
& $desktop -Application Installer -BuildId SOURCE-INSTALLER-113 -ProductVersion 1.1.3 `
    -NativeMetadataRoot $metadata
& $desktop -Application Configurator -BuildId SOURCE-CLEAN-113 -ProductVersion 1.1.3 `
    -NativeMetadataRoot $metadata -NativeFlavor Clean
& $desktop -Application Configurator -BuildId SOURCE-DIRTY-113 -ProductVersion 1.1.3 `
    -NativeMetadataRoot $metadata -NativeFlavor Dirty
```

Bundle the selected DLL, matching runtime contract and Installer built with the same profiles. Populate native buildId/dllSha256/buildFlavor/commonCoreSha256 from metadata.json, recalculate every payload size/SHA-256, then pass the normal package validator. The generator does not create ZIPs or releases. Installer binds INSTALL_ROOT/vrmod/config to the selected configuration directory; Configurator intentionally rejects an uninstalled template.

## commonCoreSha256

GF2VR-COMMON-SOURCE-MANIFEST-V1 normalizes paths of regular files under common to / and sorts them ordinally. Write the header and rows below as UTF-8 without a BOM. \t denotes tab and \n denotes LF. The uppercase SHA-256 of these bytes is commonCoreSha256. It does not reproduce legacy AFBB… identity, include overlays/compiler output, or attest to runtime success. Actual DLL hashes remain separately pinned.

```text
GF2VR-COMMON-SOURCE-MANIFEST-V1\n
relative/path\tUPPERCASE_FILE_SHA256\n
```
